## Acceptance Criteria

### AC1 - Display "Activity dates" page

**GIVEN** I am viewing the task list (see [ML-9: View the task list](./ML-9.view.the.task.list.md))

**WHEN** I select the "Activity dates" task

**THEN** the "Activity dates" page is displayed:

- the page will appear as per the prototype
- the project name will appear as the page caption
- the start date and end date fields will be blank initially
- if I have previously provided information on this page then that data will be pre-populated

### AC2 - Validate the start date

**GIVEN** I am viewing the "Activity dates" page

**WHEN** I select the "Save and continue" button

**THEN** the following validation will be performed on the start date:

- **Mandatory field** - if I have not provided a start date, display the following error: "Enter the start date"
- **Partial dates** - if I have provided a partial date (e.g. only day and month, or only year), display the following error: "Start date must include a day, month and year"
- **Non-existent dates** - if I have provided a date that does not exist (e.g. 31st February), display the following error: "Start date must be a real date"
- **Past dates** - if I have provided a date that is in the past, display the following error: "Start date must be today or in the future"

### AC3 - Validate the end date

**GIVEN** I am viewing the "Activity dates" page

**WHEN** I select the "Save and continue" button

**THEN** the following validation will be performed on the end date:

- **Mandatory field** - if I have not provided an end date, display the following error: "Enter the end date"
- **Partial dates** - if I have provided a partial date (e.g. only day and month, or only year), display the following error: "End date must include a day, month and year"
- **Non-existent dates** - if I have provided a date that does not exist (e.g. 31st February), display the following error: "End date must be a real date"
- **Past dates** - if I have provided a date that is in the past, display the following error: "End date must be today or in the future"

### AC4 - Validate date order

**GIVEN** I am viewing the "Activity dates" page

**WHEN** I select the "Save and continue" button  
**AND** both start date and end date have passed individual validation

**THEN** the following validation will be performed:

- **Date order** - if the end date is before the start date, display the following error: "End date must be the same as or after the start date"

### AC5 - Save the activity dates

**GIVEN** I am viewing the "Activity dates" page

**WHEN** I select the "Save and continue" button  
**AND** all the validation in the previous ACs is passed

**THEN** the activity dates will be saved  
**AND** I will be returned to the task list  
**AND** the "Activity dates" task will be marked as "Completed"

### AC6 - "Cancel" option / "Back" link

**GIVEN** I am viewing the "Activity dates" page

**WHEN** I select the "Cancel" option or the "Back" link

**THEN** I am returned to the task list:

- the status of the task will not be updated
- any changes I have made on the page during this visit are not saved

## Standard Behaviour

**"Back" link** - when I select the "Back" link (if present), I will be returned to the page I was on immediately prior to the current page. Any changes I made on the current page will be discarded.

**"Cancel" link** - when I select the "Cancel" link (if present) I will be returned to the task list. Any changes I made on the current page will be discarded.

**Displaying validation errors** - if any validation errors are triggered, they will be displayed in standard GDS format i.e. [error summary](https://design-system.service.gov.uk/components/error-summary/) at the top of the page, and [error message](https://design-system.service.gov.uk/components/error-message/) against the specific item that triggered the error. The wording of error messages should be verified against the data dictionary.

**Date input pattern** - date inputs follow the GOV.UK Design System [date input pattern](https://design-system.service.gov.uk/components/date-input/) with separate fields for day, month, and year to improve accessibility and user experience.
